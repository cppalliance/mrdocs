= Doxygen Compatibility

// Maintainer note. The command tables on this page are checked against the
// parser by utils/docs/check_commands_registry.py. Each table row is four
// cells, one per line: the command spellings, the status, the effect or
// replacement, and a link, which may be empty. The header row is written on
// one line, and no cell wraps onto a second line. In the first cell every
// spelling sits in its own backtick span, and only the opening `@word` of a
// span is looked up, so `@code ... @endcode` names `code`. The status is
// exactly one of Supported, Different idiom, Not supported, or MrDocs only.
// A Supported or MrDocs only row must name commands the parser dispatches,
// and every dispatched command must have such a row. A dispatched command
// named in any other row is an error. The commands in `EXEMPT_COMMANDS` in
// the script are exempt from both rules, and the page lists them as Not
// supported. Spellings without a word, such as `@f$` or `@{`, are not
// looked up.

MrDocs reads the doc comments of a C++ project that already uses Doxygen, but it is not a Doxygen clone. This page answers the question a migrating project asks first: which Doxygen commands does MrDocs understand, and what happens to the ones it does not. The xref:commands/reference.adoc[Commands Reference] lists what MrDocs understands. This page lists what Doxygen has.

== Comment styles

MrDocs accepts the same comment styles as Doxygen:

* `pass:[/** ... */]`, the Javadoc style.
* `pass:[/*! ... */]`, the Qt style.
* `pass:[///]`, a run of line comments.
* `pass:[//!]`, a run of line comments in the Qt style.
* `pass:[///<]`, `pass:[//!<]`, `pass:[/**<]`, and `pass:[/*!<]`, which document the declaration to their left, such as a member variable or an enumerator.

A command can start with a backslash or with an `@`. The two are the same, and the tables below use the `@` spelling. Plain `//` and `pass:[/* ... */]` comments are not doc comments and are ignored.

The brief is the whole first paragraph of the comment, up to the first blank line or block command. With `JAVADOC_AUTOBRIEF` or `QT_AUTOBRIEF` on, Doxygen takes the first sentence; otherwise it needs `@brief` or a one-line `///` comment. Write a short first paragraph, or set the brief explicitly with `@brief`. With xref:configuration/reference.adoc#auto-brief_option[`auto-brief`] set to `false`, MrDocs sets no brief unless the comment uses `@brief`, `@short`, `@copybrief` or `@copydoc`.

== Commands

Each table row names one or more commands and gives their status:

* *Supported*: MrDocs understands the command. The Effect column says what it produces, and the More column links the matching entry of the Commands Reference.
* *Different idiom*: MrDocs does the same job another way. The Effect column says how.
* *Not supported*: MrDocs does not understand the command. The Effect column says what happens to the text, because most of these commands do not fail loudly. The More column links the issue that tracks the gap, when there is one.
* *MrDocs only*: the command has no Doxygen counterpart. Only the last table uses this status.

A command that closes another, such as `@endcode`, is listed on the row of the command that opens it.

MrDocs does not warn about a command it ignores. The issue https://github.com/cppalliance/mrdocs/issues/1369[#1369^] asks for a warning.

=== Escape sequences

The escapes `+\@+`, `+\&+`, `+\#+`, `+\%+`, `+\"+`, `+\.+`, `+\::+`, `+\|+`, `+\--+`, `+\---+`, `+\=+`, `+\?+`, and `+\!+` are supported: each produces the text that follows the backslash. `+\$+`, `+\<+`, and `+\>+` are not: Clang removes the backslash first, so `+\$5 or \$6+` becomes inline math and `+\<em\>X\</em\>+` becomes emphasis. `+\\+` is not supported either: both characters are dropped. `+\~+` is not supported either: the tilde is shown, and the language that follows it is not used to filter the text.

== Idioms that replace Doxygen markup

Doxygen often needs markup in the comments or in the source to hide, shorten, or split documentation. MrDocs usually does the same job from the configuration.

Hiding a symbol::
Doxygen uses `@internal`, `@cond`, or `EXCLUDE_SYMBOLS`. In MrDocs, the xref:configuration/reference.adoc#exclude-symbols_option[`exclude-symbols`] option drops every symbol that matches one of its patterns, and xref:configuration/filters.adoc[Filters] describes the other filters. Because the symbol leaves the corpus, a reference to it renders as its literal name.

Types callers should not name::
Doxygen projects often use a documentation-only macro. In MrDocs, the xref:configuration/reference.adoc#implementation-defined_option[`implementation-defined`] option, or the xref:commands/reference.adoc#cmd-implementation-defined[`@implementationdefined`] command on the declaration, drops the page of the symbol and renders every reference to it as `+/* implementation-defined */+`.

Exposition-only synopses::
The xref:configuration/reference.adoc#see-below_option[`see-below`] option, or the xref:commands/reference.adoc#cmd-see-below[`@seebelow`] command, keeps the page of the symbol but collapses its synopsis to `+/* see-below */+`.

Documentation for different audiences::
Doxygen uses `ENABLED_SECTIONS` with `@if`, or a second Doxyfile. In MrDocs, write one configuration file per audience and run MrDocs once for each, with xref:configuration/reference.adoc#config_option[`--config`]. Each file has its own filters, such as `include-symbols`, `exclude-symbols`, and xref:configuration/reference.adoc#extract-private_option[`extract-private`], and its own output directory. The xref:migration-notes.adoc#idioms-without-workarounds[Migration Notes] show the idioms side by side.

== Other differences

* MrDocs links a name to its symbol only where a command asks for it. Doxygen links names it recognizes in plain text. See https://github.com/cppalliance/mrdocs/issues/1208[#1208^].
* MrDocs reads part of Markdown and HTML, not all of it. The xref:commands/inlines.adoc[Inline Commands] page lists what works. See https://github.com/cppalliance/mrdocs/issues/1291[#1291^].
